📘 Projeto Diário Online

Aplicação full-stack: uma pessoa cria conta, faz login e registra anotações pessoais (data, título, descrição, avaliação). A interface web (Angular) conversa com uma API (Spring Boot) que grava em um banco relacional (MySQL), protegida por JWT.

Relacionamento 1:N: uma conta pode ter muitas anotações; cada anotação pertence a uma conta. A tabela de anotações guarda uma chave estrangeira (FK) para a conta.

Atenção (prova): há uma restrição para evitar mais de uma anotação da mesma conta na mesma data — confirme no SQL se foi feita por chave única (UNIQUE) ou outro mecanismo.

🔐 Autenticação JWT

JWT = JSON Web Token. Depois de validar as credenciais, o backend emite um token assinado. O frontend envia esse token nas requisições protegidas, geralmente no cabeçalho Authorization.

  1. O usuário envia e-mail e senha.
  2. O backend valida as credenciais.
  3. O backend gera um token.
  4. O frontend gerencia o token.
  5. O token é enviado nas requisições protegidas.
  6. O backend valida o token antes de liberar o recurso.

🛡️ Pontos de segurança levantados

1. Senhas: o projeto usava MD5 sem salt — inadequado. Prefira BCrypt ou Argon2.
2. Chave JWT fixa no código: mantenha o segredo em variável de ambiente / gerenciador de segredos, fora do repositório.
3. Bug de config: o Docker Compose passava JWT_SECRET, mas JwtUtil não usava essa variável — a config externa não tinha efeito.
4. .env com segredos: não versione deploy/.env nem docker-compose.override.yaml com credenciais reais.

Por que não colocar tudo no Controller? A tela ficaria validando regras, montando SQL e manipulando resultados; a lógica não seria reutilizável; mudanças no banco afetariam a interface. Separar responsabilidades facilita testar e manter.

// INSERT com parâmetros (índices começam em 1)
String sql = "INSERT INTO tb_cliente (nome, telefone) VALUES (?, ?)";
PreparedStatement stmt = conexao.prepareStatement(sql);
stmt.setString(1, cliente.getNome());
stmt.setString(2, cliente.getTelefone());
stmt.executeUpdate();
// SELECT e ResultSet
String sql = "SELECT id, nome FROM tb_cliente ORDER BY nome";
ResultSet rs = stmt.executeQuery();
while (rs.next()) {              // next(): avança e retorna false no fim
    Long id = rs.getLong("id");
    String nome = rs.getString("nome");
}
Alerta de prova: um UPDATE ou DELETE sem WHERE altera/remove todos os registros. O PreparedStatement parametrizado também evita SQL injection.
// Regra salvar() do projeto: ID nulo = novo; ID preenchido = existente

    repositorio.inserir(objeto);   // INSERT
} else {
    repositorio.alterar(objeto);   // UPDATE
}

🔌 JDBC e o padrão DAO

JDBC é a API Java para conversar com bancos relacionais. DAO (Data Access Object) concentra o acesso a dados numa classe específica.

// try-with-resources: fecha recursos AutoCloseable mesmo com exceção
try (Connection conexao = ConnectionFactory.getConnection();
     PreparedStatement stmt = conexao.prepareStatement(sql)) {
    stmt.executeUpdate();

🗺️ JPA, Hibernate, ORM e JPQL

JPA = especificação de persistência de objetos Java. Hibernate = uma implementação dela. ORM = Object-Relational Mapping (mapeia objetos ↔ tabelas).

AnotaçãoFunção
@EntityDeclara a classe como entidade JPA
@Table(name="tb_pizza")Define o nome da tabela
@IdDefine a chave primária
@GeneratedValueConfigura a geração do identificador
@ColumnPersonaliza o mapeamento de uma coluna
@EnumeratedDefine como um enum será persistido
@Entity
@Table(name = "tb_pizza")
public class Pizza {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String sabor;
    private double preco;
}

Transação JPA

EntityTransaction tx = manager.getTransaction();
try {
    tx.begin();              // inicia
    manager.persist(pizza);
    tx.commit();             // confirma
} catch (RuntimeException e) {
    if (tx.isActive()) tx.rollback();  // desfaz
    throw e;
}
Método JPAO que faz
persist()Torna uma entidade nova gerenciada (inserção)
find()Busca entidade por classe + chave primária
merge()Mescla o estado da entidade ao contexto (atualizar)
remove()Marca entidade gerenciada para remoção

SQL × JPQL

-- SQL: tabela/colunas
SELECT * FROM tb_pizza ORDER BY sabor;

-- JPQL: entidade/atributos Java
SELECT p FROM Pizza p ORDER BY p.sabor
Em JPQL, Pizza é o nome da entidade e p.sabor é um atributo Java — não necessariamente o nome físico da coluna.

🧬 Orientação a objetos

Encapsulamento

Atributos private; getters/setters dão acesso controlado.

Generics — InterfaceDao<T>

public interface InterfaceDao<T> {
    void inserir(T objeto);
    void alterar(T objeto);
    void excluir(Long id);
    List<T> listar();
}

T é um parâmetro de tipo: a mesma interface serve para Cliente e Pizza. Define o contrato, não como cada classe acessa o banco.

Enum

public enum TipoPizza { DOCE, SALGADA }

Enum limita os valores a um conjunto fixo. values() retorna um array com todas as constantes.

Lombok @Data & LocalDate

@Data (Lombok) gera getters, setters, equals(), hashCode() e toString() em tempo de compilação. LocalDate = data sem horário; LocalDateTime = data + hora.

✅ Validação, exceções e qualidade

if (cliente.getNome() == null || cliente.getNome().isBlank()) {
    throw new IllegalArgumentException("Nome obrigatório");
}

isBlank() = string vazia ou só espaços. Verificar null antes evita NullPointerException.

try código que pode falhar catch trata a exceção throw lança exceção finally finalização sempre executa RuntimeException não verificada

Validações típicas de Pizza

  • Sabor informado e não só espaços.
  • Tipo e tamanho selecionados.
  • Preço válido → rejeitar com preco <= 0 (zero e negativos).
  • Tratar falhas de persistência sem mensagens confusas.

🔎 Roteiro para ler um método desconhecido na prova

  1. Identifique a camada (Controller/Service/DAO/Repository/Model).
  2. Localize a entrada (parâmetro, campo da tela, ID).
  3. Procure condições (if, null, strings vazias).
  4. Identifique a operação (INSERT/SELECT/UPDATE/DELETE ou persist/find/merge/remove).
  5. Veja como o resultado é tratado (lista, objeto, exceção, mensagem).
  6. Confira o que pode dar errado (ID inexistente, campo vazio, conexão fechada, transação não confirmada).

Relacionamentos (como ler/desenhar)

  • Associação 1:N — Cliente (1) ——< (N) Pedido: um cliente faz vários pedidos.
  • Composição — Pedido ◆——< ItemPedido: o item não existe sem o pedido (losango preenchido no lado do todo).
  • Associação N:1 — ItemPedido (N) >—— (1) Pizza: muitos itens referenciam uma pizza.
  • Dependência de enum — Pizza ----> Tamanho / TipoPizza (seta tracejada).
  • Realização — ClienteDao ....▷ InterfaceDao<Cliente>: a classe implementa a interface (seta tracejada com triângulo vazado).

Multiplicidade

Passo a passo pra criar UML do zero na prova:
  1. Leia o tema e grife os substantivos → viram classes (Cliente, Pizza, Pedido...).
  2. Grife os adjetivos/dados → viram atributos (nome, preço, data...).
  3. Grife os verbos → viram métodos (salvar, listar, calcular...).
  4. Defina relacionamentos e multiplicidade (1:N, N:1, composição).
  5. Valores fixos (status, tipo, tamanho) → enum.
  6. Monte as 3 divisões de cada classe: nome | atributos | métodos.
